
# Правила разработки

1. Перед изменениями изучай существующую структуру проекта.
2. Не переписывай работающий код без необходимости.
3. Не усложняй архитектуру без веской причины.
4. Пиши понятный, читаемый и поддерживаемый код.
5. Разбивай большие задачи на небольшие этапы.
6. После изменений запускай подходящие тесты.
7. Не удаляй файлы и данные без согласования.
8. Объясняй важные изменения простым языком.
9. Не переходи к следующему этапу, пока не проверен текущий.
10. Если обнаружена ошибка, сначала найди её причину.
